# 🫐 bbQuiz

Telegram-бот для проведения командных викторин прямо в чате.

Игроки выбирают категорию и длину игры, после чего бот по очереди показывает вопросы. Первый пользователь, который отправит правильный ответ, получает очко. Если никто не отвечает, бот постепенно показывает подсказки и затем раскрывает правильный ответ.

## Возможности

* 🎮 Викторины в групповых Telegram-чатах
* 👥 Поддержка нескольких игроков одновременно
* 🏆 Подсчёт очков для каждого пользователя
* 📊 Общий рейтинг игроков в чате
* 💡 Автоматические подсказки по таймеру
* ⏩ Возможность коллективно пропустить вопрос
* ⚙️ Настройки для каждого чата
* 🎲 Случайная выборка вопросов из базы
* 🗃️ Хранение вопросов и результатов в PostgreSQL
* 📝 Файловое логирование событий, команд и ошибок

## Как проходит игра

1. Пользователь отправляет `/start`.
2. Бот предлагает выбрать категорию.
3. После выбора категории предлагается выбрать длину игры:

   * `5` раундов
   * `15` раундов
   * `30` раундов
4. Бот загружает случайные вопросы из PostgreSQL.
5. Бот показывает вопрос всем участникам чата.
6. Первый правильный ответ приносит пользователю `+1` очко.
7. При отсутствии правильного ответа бот показывает подсказки через заданный интервал.
8. После завершения игры бот показывает результаты и сохраняет очки в базу.

По умолчанию используется 15 раундов, между подсказками проходит 7 секунд, а для коллективного пропуска вопроса требуется 2 участника.

## Команды

| Команда     | Описание                          |
| ----------- | --------------------------------- |
| `/start`    | Начать новую игру                 |
| `/stop`     | Завершить текущую игру            |
| `/skip`     | Голос за пропуск текущего вопроса |
| `/scores`   | Показать общий рейтинг чата       |
| `/settings` | Изменить настройки игры           |
| `/help`     | Показать информацию о боте        |

Во время игры команды `/stop` и `/skip` доступны для управления текущим раундом.

## Настройки

Для каждого чата отдельно сохраняются:

### Количество голосов для пропуска

Параметр `skips_need` определяет, сколько игроков должны отправить `/skip`, чтобы вопрос был пропущен.

Допустимый диапазон в текущей реализации:

```text
1–19
```

### Интервал между подсказками

Параметр `time_between_hints` задаёт время в секундах между подсказками.

Допустимый диапазон:

```text
1–60 секунд
```

Настройки сохраняются в PostgreSQL и восстанавливаются при следующем использовании бота.

## Установка

Клонируйте репозиторий:

```bash
git clone https://github.com/VitaliyArmss/bbQuiz.git
cd bbQuiz
```

Восстановите зависимости:

```bash
dotnet restore
```

Соберите проект:

```bash
dotnet build
```

## Настройка Telegram-бота

1. Откройте Telegram и найдите `@BotFather`.
2. Выполните команду `/newbot`.
3. Задайте имя и username бота.
4. Скопируйте полученный токен.

Токен нельзя публиковать в Git-репозитории.

## Настройка переменных окружения

Приложение читает две переменные:

```env
TELEGRAM_TOKEN=your_telegram_bot_token
DB_CONNECTION_STRING=Host=localhost;Port=5432;Database=bbquiz;Username=postgres;Password=your_password
```

В текущем коде `.env` загружается из директории запущенного приложения, а не напрямую из корня репозитория. Поэтому при запуске через `dotnet run` файл `.env` должен находиться рядом с собранным приложением, например:

```text
bin/Debug/net10.0/.env
```

Для опубликованной версии `.env` должен находиться рядом с исполняемым файлом.

> Никогда не добавляйте реальные токены и пароли в Git.

## База данных

Проект использует PostgreSQL.

В текущем репозитории отдельного SQL-файла с миграциями или схемой базы данных нет, поэтому таблицы необходимо создать самостоятельно.

### Таблица вопросов

Все таблицы категорий должны иметь как минимум поля:

```sql
question
answer
```

Для случайной выборки бот объединяет категории через `UNION ALL`, поэтому структура таблиц категорий должна быть совместимой.

Например:

```sql
CREATE TABLE cinema (
    question TEXT NOT NULL,
    answer TEXT NOT NULL
);

CREATE TABLE music (
    question TEXT NOT NULL,
    answer TEXT NOT NULL
);

CREATE TABLE food (
    question TEXT NOT NULL,
    answer TEXT NOT NULL
);

CREATE TABLE nature (
    question TEXT NOT NULL,
    answer TEXT NOT NULL
);

CREATE TABLE geography (
    question TEXT NOT NULL,
    answer TEXT NOT NULL
);

CREATE TABLE videogames (
    question TEXT NOT NULL,
    answer TEXT NOT NULL
);
```

При необходимости можно добавить таблицу `locale`:

```sql
CREATE TABLE locale (
    question TEXT NOT NULL,
    answer TEXT NOT NULL
);
```

### Таблица настроек чатов

Бот использует таблицу `chatsettings`:

```sql
CREATE TABLE chatsettings (
    chat_id BIGINT PRIMARY KEY,
    skips_need INTEGER,
    time_between_hints INTEGER
);
```

Значения по умолчанию:

```text
skips_need = 2
time_between_hints = 7
```

Эти названия и порядок полей соответствуют текущему коду.

### Таблица результатов

Для хранения накопленных очков используется таблица `scores`:

```sql
CREATE TABLE scores (
    chat_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    score INTEGER NOT NULL DEFAULT 0,
    user_name TEXT NOT NULL,
    PRIMARY KEY (chat_id, user_id)
);
```

Очки пользователя сохраняются отдельно для каждого чата. При повторном завершении игры его новый результат добавляется к уже существующему.

## Добавление вопросов

Пример добавления вопросов:

```sql
INSERT INTO cinema (question, answer)
VALUES
    ('Кто сыграл Джека Воробья?', 'Джонни Депп'),
    ('Как называется первый фильм серии «Матрица»?', 'Матрица');

INSERT INTO music (question, answer)
VALUES
    ('Какая группа исполнила песню Bohemian Rhapsody?', 'Queen');

INSERT INTO geography (question, answer)
VALUES
    ('Столица Франции?', 'Париж');
```

Ответ сравнивается без учёта регистра, поэтому:

```text
Париж
париж
ПАРИЖ
```

будут считаться одинаковыми.

## Архитектура

Упрощённая схема взаимодействия компонентов:

```text
Telegram
   │
   ▼
UpdateHandler
   │
   ├── команды ───────► CommandHandler
   │
   ├── кнопки ────────► Keyboards
   │
   └── ответы
         │
         ▼
      BotLogic
         │
         ├── GameState
         │
         ├── ChatSettings
         │
         └── PostgreSQL
                ├── вопросы
                ├── chatsettings
                └── scores
```

Игры хранятся в памяти процесса в `ConcurrentDictionary`, а долгосрочные настройки и результаты — в PostgreSQL.

## Игровая механика

За каждый правильный ответ игрок получает:

```text
+1 очко
```

После правильного ответа текущий вопрос завершается и начинается следующий.

Если никто не ответил:

1. через установленный интервал появляется первая подсказка;
2. ещё через один интервал появляется вторая подсказка;
3. затем вопрос завершается, а бот показывает правильный ответ.

Подсказки формируются на основе самого ответа: часть букв открывается случайным образом, а остальные заменяются на `_`.

## Особенности

* Одна игра привязана к конкретному Telegram-чату.
* Одновременно для чата может существовать только одна активная игра.
* `/skip` требует нескольких участников и защищён от повторного голоса одного и того же пользователя.
* Если несколько раундов подряд никто не взаимодействует с игрой, бот автоматически завершает её.
* При завершении игры результаты сохраняются в PostgreSQL.
